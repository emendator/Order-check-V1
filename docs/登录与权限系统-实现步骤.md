## 实现总原则

- **零新增后端依赖**：密码哈希用 `hashlib.pbkdf2_hmac`，token 用 Session Token（存 `users.token`），邀请码用 `secrets` —— 全部标准库
- **零新增前端路由依赖**：不引入 react-router，用 `AuthContext` + 页面状态机切换
- 沿用现有代码风格：API 统一返回 `{success, data, message}`；SQLAlchemy 模型 + crud 函数 + main 路由三层
- 每个阶段完成后可独立验证

### 步骤 4: 新增 `backend/auth.py`

```python
import hashlib, hmac, secrets
from fastapi import Depends, HTTPException, Header
from sqlalchemy.orm import Session
from database import get_db
from models import User

def hash_password(password: str) -> str:
    salt = secrets.token_hex(16)
    h = hashlib.pbkdf2_hmac("sha256", password.encode(), bytes.fromhex(salt), 100_000)
    return f"pbkdf2$100000${salt}${h.hex()}"

def verify_password(password: str, stored: str) -> bool:
    try:
        _, iters, salt, expected = stored.split("$")
        h = hashlib.pbkdf2_hmac("sha256", password.encode(), bytes.fromhex(salt), int(iters))
        return hmac.compare_digest(h.hex(), expected)
    except Exception:
        return False

def generate_token() -> str:
    return secrets.token_urlsafe(32)

def get_current_user(authorization: str = Header(None), db: Session = Depends(get_db)) -> User:
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(401, "未登录")
    token = authorization.removeprefix("Bearer ").strip()
    user = db.query(User).filter(User.token == token).first()
    if not user:
        raise HTTPException(401, "登录已失效，请重新登录")
    if user.status == "expired":
        raise HTTPException(403, "账号已到期，请联系管理员延长有效期")
    if user.status == "pending_company":
        raise HTTPException(403, "请先完成公司设置")
    if user.status != "active":
        raise HTTPException(403, "账号已被禁用")
    return user

def require_role(*roles):
    def dep(user: User = Depends(get_current_user)):
        if user.role not in roles:
            raise HTTPException(403, "无权限执行此操作")
        return user
    return dep
```

```python
class CompanySetupBody(BaseModel):
    action: str  # "join" | "create"
    company_name: str; company_password: str

# join: 校验公司存在 + 密码正确 → 绑定 company_id，status=active
# create: 校验公司名唯一 → 创建公司(created_by=当前用户) → 绑定 → status=active
```

**登录（`POST /api/auth/login`）**：

```python
class LoginBody(BaseModel):
    username: str; password: str

# 1. 查用户，verify_password
# 2. 未找到/密码错 → 统一 401 "用户名或密码错误"
# 3. status=pending_company → 403 "请先完成公司设置"（前端跳公司设置页）
# 4. valid_until 过期 → status=expired → 403 "账号已到期，请联系管理员延长有效期"
# 5. 生成 token，更新 last_login_at，返回 {"token", "user": {...days_left}}
```

**修改自己密码（`PUT /api/auth/password`）**：校验旧密码 → 更新哈希。

**公司密码（`PUT /api/companies/password`）**：`require_role("admin","super_admin")`，校验旧密码 → 更新本公司密码。

**公司存在检查（`GET /api/companies/check`）**：返回 `{exists: bool}`。

```python
def expire_accounts():
    db = SessionLocal()
    try:
        now = datetime.utcnow()
        rows = db.query(User).filter(
            User.status == "active",
            User.valid_until.isnot(None),
            User.valid_until <= now,
        ).update({User.status: "expired", User.token: None}, synchronize_session=False)
```

## 第三阶段补充：游客模式（免密体验）

### 步骤 18.1: 后端

1. `models.py`：`User` 增加 `is_guest`（Boolean，默认 False）；`to_dict()` 包含该字段
2. `database.py`：`init_db()` 迁移列表增加 `ALTER TABLE users ADD COLUMN is_guest BOOLEAN DEFAULT 0`
3. `seed.py`：创建固定游客账号 `guest`（`is_guest=True`，role=`user`，随机密码不可登录，邮箱 `guest@guest.local`，永久有效，无公司）
4. `main.py`：
   - 新增 `POST /api/auth/guest-login`：查 `User.is_guest == True`，生成新 token，返回 `{token, user}`，提示"数据不会保留"
   - `POST /api/auth/logout`：若用户 `is_guest`，先删除其全部订单（`Order.owner_id == user.id`），再清 token
5. `scheduler.py`：新增 `cleanup_guest_data`（每小时）：游客未登录（token 为空）时清理其残留订单

### 步骤 18.2: 前端

1. `types/index.ts`：`UserInfo` 增加 `is_guest: boolean`
2. `api/index.ts`：新增 `guestLogin()` → `POST /auth/guest-login`；`logout(token?)` 支持显式传 token（修复拦截器时序丢 token 问题）
3. `AuthContext.tsx`：新增 `guestLogin()`；`logout()` 先读取 token 显式传给后端，再清本地
4. `Login.tsx`：登录 Tab 下方加分隔线 + "以游客身份登录"按钮 + 警示 Alert（不保留数据）
5. `Dashboard.tsx`：游客横幅 Alert（`user.is_guest`）；角色标签 `RoleTag` 增加 `isGuest` 判断，游客显示紫色"游客"

### 步骤 18.3: 关键 Bug（退出未清数据）

- **现象**：点击退出后游客订单未删除、token 未清
- **根因**：`AuthContext.logout()` 中 `apiLogout()` 调用后**同步**执行 `localStorage.removeItem`，而 axios 请求拦截器在**微任务**中才读取 localStorage → 读到 null → logout 请求不带 `Authorization` 头 → 后端幂等返回 200 但未清除
- **修复**：`logout(token?)` 显式接收 token 并放入请求头；`AuthContext.logout` 先取 token 再传，不依赖拦截器

4. 再次游客登录 → 无残留数据
5. 前端登录页有游客按钮+警示；Dashboard 有游客横幅；角色标签显示"游客"（紫色）

## 关键风险与注意事项

| 风险 | 对策 |
| ------ | ------ |
| passlib/bcrypt 版本兼容坑 | 用标准库 pbkdf2，绕开 |
| JWT 无法主动失效 | 用 Session Token（存库），禁用即清 token |
| pending_company 账号无法登录但需完成公司设置 | 单独 `get_pending_user` 依赖，仅校验 token 存在 |
| 订单隔离遗漏某个接口 | 逐个核对 main.py 中 16 个订单路由全部加 owner 过滤 |
| 清除账号误删他人数据 | 级联仅限"该管理员分发的二级邀请码注册的用户"，且查询用邀请码链 |
| 历史订单归属 | seed 时一次性划归超级管理员 |
| 时间比较 | 全项目统一 `datetime.utcnow()`（与现有代码一致） |
