# 订单查重管理系统

一个**多公司、多账户、三级权限**的订单查重工具：批量导入订单表格时，自动识别**重复收件人**，从根源上避免重复发货。

## 项目简介

电商、仓储、代发等场景中，同一批订单常由多人、多张表格分头录入。一旦同一收件人被重复录入，就会造成**重复发货**——多付一次运费和货物，且事后难以追溯。

本系统把「订单表格」变成可查询、可查重的数据库记录：

- **导入即查重**：支持 `.xlsx` / `.xls` / `.csv`，可一次导入多个文件，导入时自动识别表头并检测重复；
- **四重匹配**：以「姓名 + 地址 + 电话 + 产品型号」为判定键，全角/半角差异不会造成漏判；
- **逐组审查**：重复记录分组展示，你选择保留哪一条，其余被确认的重复项**物理删除**，而不是只打个标记；
- **自动过期**：导入 3 天后数据自动清理，无需人工维护。

适合自建、单人或多团队使用；数据默认保存在本地 SQLite 文件中，不依赖外部数据库服务。

## 系统架构

```
浏览器（React SPA，开发端口 3000）
   │  axios 请求 /api/**（自动携带 Bearer Token）
   ▼
Vite 开发代理 / Nginx 生产反向代理
   ▼
FastAPI 后端（backend/main.py，默认端口 8001）
   ├─ auth.py              会话 Token 校验与角色鉴权
   ├─ main.py              31 个 REST 接口（认证/公司/邀请码/用户/上传/订单/查重）
   ├─ crud.py              业务层数据读写
   ├─ models.py            4 张表的 ORM 定义（orders / users / companies / invite_codes）
   ├─ database.py          SQLAlchemy 连接 SQLite（data/orders.db）
   ├─ excel_parser.py      表格解析 + 表头别名模糊匹配
   ├─ duplicate_checker.py 四重重复检测
   └─ scheduler.py         后台定时清理（过期订单 / 到期账号 / 空公司 / 游客残留）
```

**推荐读代码顺序**

1. 数据长什么样 → `backend/models.py`、`backend/database.py`
2. 请求进来做什么 → `backend/main.py`（全部路由入口）
3. 表格如何变成订单 → `backend/excel_parser.py` → `backend/duplicate_checker.py` → `backend/crud.py`
4. 界面按钮对应哪个页面 → `frontend/src/App.tsx` → `frontend/src/pages/` → `frontend/src/components/`
5. 前端如何调后端 → `frontend/src/api/index.ts`（全部接口封装都在这一个文件）

## 快速开始

### 环境要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.9+ | 受 `pandas 2.1.4` 最低版本约束 |
| Node.js | 18+ | `deploy/deploy.sh` 使用 20 LTS |
| npm | 随 Node.js | 用于安装前端依赖 |

不需要预先安装数据库——首次启动会自动创建 SQLite 文件。

### 方式一：Windows 一键启动

双击项目根目录的 `启动.bat`。脚本会依次安装 Python 与 npm 依赖、清理 3000 / 8001 端口占用、后台启动前后端，并自动打开浏览器。

启动成功后终端会显示：

```
系统启动完成！
前端地址: http://localhost:3000
后端 API: http://localhost:8001/docs
```

若浏览器未自动打开，手动访问 <http://localhost:3000>。

### 方式二：手动启动（全平台）

```bash
# 终端 1 —— 后端（端口 8001）
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8001 --reload

# 终端 2 —— 前端（端口 3000）
cd frontend
npm install
npm run dev
```

- 前端页面：<http://localhost:3000>
- 后端接口文档（Swagger UI）：<http://localhost:8001/docs>
- `frontend/vite.config.ts` 已配置代理：浏览器请求 `/api/**` 自动转发到 `http://localhost:8001`

### 首次登录

首次启动时，`backend/seed.py` 会自动创建预置的超级管理员与公司账号（幂等，重复启动不会重建）。

> ⚠️ **安全提示**：预置账号由 `backend/seed.py` 创建，其默认口令 `123123` 直接写在源码里——任何能看到源码的人都能登录未改过口令的实例。正式部署前请用环境变量覆盖，见下一节。

### 修改超级管理员信息

超级管理员与预置公司**只在首次启动、数据库中还不存在该账号时创建一次**（`seed.py` 是幂等的）。所以「改配置」和「改已有数据」是两条不同的路径。

**一、首次初始化前，用环境变量指定（推荐）**

启动后端前设置以下环境变量，`seed.py` 会优先读取：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SUPER_ADMIN_USERNAME` | `admin` | 超级管理员用户名 |
| `SUPER_ADMIN_PASSWORD` | `123123` | 超级管理员登录口令 |
| `SUPER_ADMIN_COMPANY` | `我的公司` | 预置公司名称 |
| `SUPER_ADMIN_EMAIL` | `admin@example.com` | 超级管理员邮箱 |

```bash
# Windows PowerShell
$env:SUPER_ADMIN_PASSWORD = "换成一个强口令"
cd backend; python -m uvicorn main:app --host 127.0.0.1 --port 8001

# Linux / macOS
export SUPER_ADMIN_PASSWORD="换成一个强口令"
cd backend && python -m uvicorn main:app --host 127.0.0.1 --port 8001
```

**二、已经初始化之后，在界面里改**

| 要改什么 | 怎么改 |
| --- | --- |
| 登录口令 | 顶栏用户菜单 →「修改登录密码」；接口 `PUT /api/auth/password` |
| 公司密码 | 「用户管理 → 修改公司密码」；接口 `PUT /api/companies/password` |
| 账号有效期 | 「用户管理 → 账号管理 → 延长有效期」；接口 `PUT /api/admin/users/{id}/extend` |

> 修改登录密码**不会**让已登录的会话立即失效（`users.token` 不会被清除），必要时请在「用户管理」中清除该账号。

**三、用户名 / 邮箱 / 公司名没有修改入口**

这三个字段只在首次创建时写入，界面与后端都没有提供修改接口，公司名创建后即固定。需要变更时只能二选一：

1. **删除 `data/orders.db` 后重新初始化**——按上面的方式设好环境变量，删库重启即可重建账号与公司，但**原有订单与账号数据会全部丢失**（先备份）；
2. **直接改数据库**——用 SQLite 客户端修改 `data/orders.db` 中 `users` / `companies` 表的对应字段。

### 第一次导入与查重

1. 点击 **「上传表格」**，拖入一个或多个 `.xlsx` / `.xls` / `.csv` 文件；
2. 系统自动匹配列名（姓名、地址、电话、**产品型号**），未匹配到可点 ⚙️ 手动指定；**产品型号列缺失将无法导入**；
3. 每个文件可单独设置「已发货 / 未发货」，确认后点 **「导入全部」**；
4. 若发现重复，表格中重复行标红，页面顶部出现红色告警横幅；
5. 点击 **「重复审查」** 只显示待处理重复项，点该行的 **「处理重复」**，在弹窗中**选择要保留的一条**并确认；
6. 其余被确认的重复记录会被**物理删除（不可恢复）**，该组只剩你保留的那条。

> 设计取舍：确认重复后直接删除、而不是保留并打上「已处理」标记，是为了避免「标记掩盖真实重复」——若只是打标，重复数据仍在库中，仍可能被误发。

## 重复判定规则

```
判定键   ：姓名 + 地址 + 电话 + 产品型号（产品型号必填）
标准化   ：strip 去空白 + Unicode NFKC 规范化（全角→半角）
判定条件 ：同一判定键下存在 ≥2 条未过期记录，且其中至少 1 条未处理
特殊规则 ：已处理记录仍参与比对（杜绝「打标掩盖真实重复」）；
           仅当一组内全部记录都已处理时，才不再提示
```

## 权限与安全

```
权限层级 ：super_admin > admin > user
密码存储 ：pbkdf2_hmac(SHA-256, 100000 次迭代, 随机盐)，恒定时间比较
会话认证 ：随机会话 Token 存于 users.token，登出或账号禁用即失效
接口鉴权 ：依赖注入校验 Token + 账号状态（active）
数据隔离 ：orders.owner_id 过滤，各账户订单互不可见
响应安全 ：模型序列化永不输出 password_hash 与 token
订单过期 ：导入后 3 天自动清理（backend/models.py 的 timedelta(days=3)）
```

### 已知限制

- **预置口令**：`backend/seed.py` 内置默认口令且已进入版本库，公网部署前必须修改（见上文安全提示）。
- **单进程运行**：SQLite + 内存缓存，后端必须单 worker 运行（见 `deploy/order-check.service` 注释），不适合高并发场景。
- **无内置 HTTPS**：生产环境需由反向代理（Nginx 等）终止 TLS。
- **会话 Token 明文存库**：`users.token` 未加密存储，数据库文件泄露等同于会话泄露——请妥善保管 `data/orders.db`。
- **无环境变量机制**：当前配置项均为源码常量，详见「配置说明」。

### 后端 `backend/`

| 文件 | 职责 |
| --- | --- |
| `main.py` | 应用入口，定义 31 个 REST 接口（认证 / 公司 / 邀请码 / 用户 / 上传 / 订单 / 查重）与全局异常处理、CORS |
| `database.py` | SQLAlchemy 连接 SQLite；会话工厂与依赖注入；建表与「缺列补列」轻量迁移 |
| `models.py` | 4 张表的 ORM 定义与过期时间计算；序列化永不泄露密码 |
| `auth.py` | 密码哈希与校验、会话 Token 与邀请码生成、角色鉴权依赖 |
| `seed.py` | 首次启动的预置数据（幂等）：超级管理员、公司、游客账号、历史数据归属迁移 |
| `crud.py` | 业务层数据操作：订单增删改查分页、重复组聚合、用户/公司/邀请码管理 |
| `excel_parser.py` | `.xlsx` / `.xls` / `.csv` 解析与表头中英文别名模糊匹配 |
| `duplicate_checker.py` | 四重匹配去重算法（NFKC 标准化后比较） |
| `scheduler.py` | APScheduler 定时任务：清理过期订单、到期账号、空公司与游客残留 |
| `requirements.txt` | Python 依赖清单（版本锁定） |

依赖方向：`main.py`（路由）→ `crud.py`（操作）→ `models.py`（表结构）；`main.py` 另调用 `auth.py`、`excel_parser.py`、`duplicate_checker.py`、`scheduler.py`、`seed.py`。

## 常见问题

**Q：数据保存在哪里？如何备份？**
全部数据在项目根目录的 `data/orders.db`。**复制这个文件即完成备份**，下次启动会自动使用它。建议定期复制到其他位置。

**Q：忘记密码怎么办？**
由管理员在「用户管理 → 账号管理」中处理（延长有效期或清除重建）。本项目没有邮件找回密码功能。

**Q：如何注册新账号？**
需要**邀请码**：超级管理员可发放一级（→ 管理员）与二级（→ 用户）邀请码，管理员只能发放二级。每个邀请码**使用一次后即作废**，不可复用；新账号有效期继承邀请码设置。

**Q：游客模式是什么？**
点击「以游客身份登录」可免注册体验全部订单功能，但**不保留任何数据**——退出登录后使用痕迹自动清除。游客没有用户管理入口。

**Q：3 天过期时间能改吗？**
可以。修改 `backend/models.py` 中的 `timedelta(days=3)`。

**Q：导入时提示「列未匹配」怎么办？**
点击对应文件行的 ⚙️ 展开配置，在「对应列」下拉框中手动选择正确列名。**产品型号列必填**，缺失时导入接口会返回 400。

**Q：能重复导入同一个文件吗？**
不能。系统按文件名校验，已导入过的同名文件会提示「文件名已存在，不允许重复导入同一文件」。

**Q：误导入了无关表格怎么办？**
在工具栏的文件名下拉框中选中该文件，点「批量处理」勾选相关行后确认删除。

**Q：端口被占用怎么办？**
修改 `frontend/vite.config.ts` 中的端口，或关闭占用 3000 / 8001 端口的程序。`启动.bat` 会先按端口清理旧进程；若 3000 被占用，Vite 会自动顺延到 3001，请按终端提示访问。

**Q：后端接口文档在哪里？**
本地启动后访问 <http://localhost:8001/docs>（Swagger UI），可在线查看并调试全部接口。

## 自行部署

`deploy/` 目录提供了一套自托管到 Linux 服务器的脚本与配置：

| 文件 | 用途 |
| --- | --- |
| `deploy/deploy.sh` | 一键部署：安装系统依赖与 Node.js、建虚拟环境装后端依赖、构建前端、配置 systemd 与 Nginx、开放防火墙端口 |
| `deploy/update.sh` | 更新：修复目录权限 → 重新构建前端 → 重启后端 |
| `deploy/order-check.service` | 后端 systemd 服务定义（单 worker 运行） |
| `deploy/nginx.conf` | Nginx 站点配置：托管前端静态产物，并将 `/api/` 反向代理到后端 |

```bash
# 在服务器上（以 Ubuntu 为例）
git clone <你的仓库地址> /opt/order-check
cd /opt/order-check
sudo bash deploy/deploy.sh        # 默认监听 80
sudo bash deploy/deploy.sh 8082   # 或指定端口
```

> ⚠️ 部署到公网前，请先修改 `backend/seed.py` 中的默认口令，并为 Nginx 配置 HTTPS 与访问控制。
